# NW-003 — 金融治理审核包交接

状态：NW-003 本地技术验收完成；最终包保持待人工签核。总验收记录见 `outputs/nw003/verification.json`。

## 这次真正打通了什么

主界面是 Aurora 家族办公室的负责人审核工作流。它读取已确认的合成 IPS、持仓和来源，实际运行七项财务控制，让本地 Qwen 调查和解释结果，再输出 JSON / Markdown / PDF 审核包。图上的节点来自真实事件，失败会保留，没有用预置结果冒充模型执行。

审核包把几件事分开：计算得到了什么、来源是否足够、模型建议做什么、负责人是否确认了这份具体版本。提案没有连接交易或外发工具。通过数字和来源链接检查，不代表模型的解释已经经过专业审核。

当前范围是一个本地操作者、一个虚构家办、七个已知案例。原黑客松界面保留在 `/legacy`；配置修复的工程证据在 `/environments`。

## 从真实业务动作理解演示

1. 打开 `/`，运行或选择 F00 的实际记录。USD 1 亿 reported NAV、30 个持仓、4 个账户都来自输入。VEGA 直接加基金穿透暴露为 10%，超过 IPS v2 的 8%；合格现金 USD 320 万，对应已确认 90 天现金需求 USD 400 万，覆盖率 0.80，缺口 USD 80 万。
2. 看 IPS v1 → v2 的规则变化和对应来源，再看 Findings / Actions。这里的价值是把哪些规则、哪些记录、哪些建议需要负责人判断连接起来，而不是让模型自己签核。
3. 在 Sources 打开具体记录，核对文件、字段、日期和哈希。PDF 的摘要和模型选择的引用只是入口；JSON 附带完整计算证据。
4. 需要测试签核时，使用明确的 test-only 操作者姓名和说明。确认包后另行接受 handoff。随后替换来源，旧决定必须失效，不能由旧标签页复用。
5. F01 是不同来源快照，暴露变成 7%、现金覆盖变成 1.55。它说明真实输入会改变计算结果，不能算作 Harness 让资产配置变好，更不是执行过交易。
6. F02 缺少基金成分，USD 400 万保持 Unknown，不重新归一成已知资产比例。F03 的新收件日期不能刷新旧 NAV。F04 的例外已到期。F05 价格冲突可以由证据支持的提取纠错生成新版本，原件保留。F06 的敌意文档没有批准或外发权限。

对外展示之前，应由真实负责人检查模型的解释及建议。尤其不能把不完整的已知暴露直接写成最终违规结论；F02 的结构化结果正确保留 needs-source，但模型摘要可能仍过度概括。

## 两次冻结试验的解释

第一轮 `nw003-20261031-v1` 完成 42/42 个真实模型试验。其旧校验器把 F05 实际读到的合法佐证 `positions.csv:P02` 错误拒绝为未绑定引用。有限来源工具还列出了当时不能读取的元数据。这是实现问题。保留的旧评分不能被解释为模型能力排名或治理的因果收益。

第二轮 `nw003-20261031-v2` 修复上述问题，独立检查引用是否存在真实读取回执。模型、数据、提示词、工具 schema、预算和配对 seeds 均与第一轮一致。没有替换第一轮失败槽位。每轮是 F00–F06 × 普通 / 受治理 × 三次，共 42 槽；七次脚本计算检查另列。

两组共享来源工具、确定性计算和隔离边界，区别是提交校验及同预算内修复机会。版本绑定和人类签核失效另有事务及浏览器验收，不能从这两个模型组的差值推算整个产品的商业收益。无外部动作也由两组共享的工具范围保障。
